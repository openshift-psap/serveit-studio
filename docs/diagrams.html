2. Optimization Pipeline (11 Steps)

The recipe-based optimizer runs up to 11 steps. Steps 2-3 and 6-11 deploy real workloads. Steps 4-5 are pure math. Optional steps (9, 10, 11) run conditionally.

3. Smart PD Search Algorithm

Calculates near-optimal P/D split from calibration data. Tests ~3 configs per TP pair instead of exhaustive search (22-46x reduction).
flowchart TD
    CAL[Steps 2-3: TP Calibration
Measure prefill & decode
throughput per TP] --> PAIRS
    PAIRS[Select top-N TP pairs
e.g. prefill_tp=8, decode_tp=1
prefill_tp=4, decode_tp=2] --> RATIO
    RATIO[Calculate throughput ratio
r = decode_thr / prefill_thr] --> IDEAL
    IDEAL["Compute ideal decode pods
D_ideal = GPUs / (r × prefill_tp + decode_tp)"] --> CANDIDATES
    CANDIDATES["Generate candidates
floor(D), ceil(D), ±1
~3 configs per TP pair"] --> NIXL
    NIXL{Asymmetric TP
check}
    NIXL -->|"prefill_tp ≤ decode_tp
OR allow_asymmetric=true"| TEST
    NIXL -->|"prefill_tp > decode_tp"| SKIP[Skip: NIXL KV transfer
crashes with asymmetric TP]
    TEST[Run benchmark
for each candidate] --> PARETO
    PARETO[Build Pareto front
TTFT P99 vs Throughput P90]
    style CAL fill:#fef3c7,stroke:#f59e0b
    style IDEAL fill:#f5f3ff,stroke:#8b5cf6
    style PARETO fill:#ecfdf5,stroke:#10b981

5. Deployment Lifecycle (PD Architecture)

Sequential deployment of prefill and decode pods. Higher GPU requirement deploys first to prevent scheduling deadlocks.
sequenceDiagram
    participant DM as Deployment Manager
    participant K as Kubernetes
    participant V as vLLM Pods
    Note over DM: Deploy highest GPU
requirement first
    DM->>K: Apply decode LWS
(e.g. TP=8, 1 pod)
    loop Wait for running
        DM->>K: Check LWS status
        K-->>DM: replicas: 0/1
        Note over DM: Poll every 5s
    end
    K-->>DM: replicas: 1/1 ✓
    DM->>K: Apply prefill LWS
(e.g. TP=4, 2 pods)
    loop Wait for running
        DM->>K: Check LWS status
        K-->>DM: replicas: 1/2
    end
    K-->>DM: replicas: 2/2 ✓
    DM->>K: Apply services
    loop Wait for model loading
        DM->>V: Stream pod logs
        V-->>DM: "Loading model..."
    end
    V-->>DM: "Application startup complete"
    Note over DM: Extract profiled
memory data from logs
    alt Pod stuck > 180s
        DM->>K: Delete stuck pod
        K->>K: LWS recreates pod
        Note over DM: Max 3 retries
    end

10. EPP Routing & Metrics-Driven Weight Derivation

The EPP scores each pod using 5 dimensions derived from real Prometheus metrics. Weights are computed mathematically, not swept as presets.
flowchart TD
    REQ[Incoming Request] --> EPP[EPP Endpoint Picker]
    EPP --> SCORE[Score each vLLM server]
    SCORE --> PC["Prefix Cache
vllm_prefix_cache_hits_rate"]
    SCORE --> KV["KV Cache
vllm_kv_cache_pct"]
    SCORE --> QU["Queue
vllm_requests_waiting"]
    SCORE --> AR["Active Requests
vllm_requests_running"]
    SCORE --> SLO["SLO (if enabled)
vllm_ttft_p99 vs target"]
    PC --> WEIGHTED["score = w1×prefix + w2×kv + w3×queue + w4×active + w5×slo"]
    KV --> WEIGHTED
    QU --> WEIGHTED
    AR --> WEIGHTED
    SLO --> WEIGHTED
    WEIGHTED --> BEST[Route to highest
scoring server]
    subgraph Derivation["Step 9: Smart Weight Derivation"]
        PROM["Prometheus Metrics

        DERIVE["Compute time impact

        DERIVE --> TEST_W["Test derived weights

        TEST_W --> CMP{Better than

        CMP -->|Yes| USE[Use derived weights]

11. Latency-Bounded Throughput Search (Step 10)

Finds maximum throughput under a user-defined latency SLA using two-phase search: exponential ramp-up then binary search.
flowchart TD
    START["Estimate starting concurrency
C₀ = throughput × (target_ms / observed_ms) × 0.6"] --> PHASE1
    subgraph PHASE1["Phase 1: Exponential Ramp-Up"]
        T1[Test at C₀] --> CHECK1{Latency < target?}
        CHECK1 -->|Yes, far from limit| DOUBLE["C = C × 2.0"]
        CHECK1 -->|Yes, approaching| BUMP["C = C × 1.2"]
        CHECK1 -->|No| FOUND[Found upper bound]
        DOUBLE --> T1
        BUMP --> T1
    end
    FOUND --> PHASE2
    subgraph PHASE2["Phase 2: Binary Search"]
        BS["low = last good C
high = first bad C"] --> MID["Test at mid = (low+high)/2"]
        MID --> CHECK2{Latency < target?}
        CHECK2 -->|Yes| UP["low = mid"]
        CHECK2 -->|No| DOWN["high = mid"]
        UP --> CONV{Converged?
within 5%}
        DOWN --> CONV
        CONV -->|No| MID
        CONV -->|Yes| RESULT["Max throughput
under SLA = low"]
    end
    style START fill:#e0f2fe,stroke:#0ea5e9
    style RESULT fill:#ecfdf5,stroke:#10b981
