GPU Split Combinations
How many Prefill TP × Decode TP combinations to explore. Steps 2-3 measure all TP values — this controls how many of those are combined for P/D testing.
▸
Controls how many of the best Prefill TP and Decode TP values (from Steps 2-3) are crossed to form TP pairs. Each pair then gets its own set of P/D ratio tests.

1 → Only the single best prefill TP × best decode TP. Fastest — 1 TP pair.
2 → Top-2 × Top-2 = up to 4 TP pairs. Good balance. Recommended.
3 → Top-3 × Top-3 = up to 9 TP pairs. More coverage.
4 → All 4 × All 4 = up to 16 TP pairs. Most thorough.
Prefill / Decode Pod Balance
For each TP pair above, how many prefill-vs-decode pod ratios to test.
▸
For each TP pair, there are many ways to split GPUs between prefill and decode pods (e.g. 2 prefill + 6 decode, or 3 prefill + 4 decode). This controls how many of those ratios are actually deployed and tested.

Smart — Uses the throughput measured in Steps 2-3 to calculate where the prefill/decode pipeline is balanced, then tests only ~3 ratios around that optimum. Much faster, same accuracy in practice.
Exhaustive — Tests every valid pod ratio for each TP pair. Guarantees no split is missed, but can run 50+ tests on large clusters.

⚙️ Advanced Settings
Fine-tune low-level engine settings. Most users should leave everything on "Auto" -- the optimizer picks good defaults for you.
▸
Value Settings
SettingDescriptionModeValue
max-model-lenMax total text length (input + output) per request. Larger values reserve more GPU memory, leaving less for KV cache (fewer concurrent users). Auto = calculated by InfeRecipe from your ISL + OSL.
gpu-memory-utilizationFraction of GPU memory the engine can use (0.0-0.99). Higher = more KV cache space for concurrent requests, but less safety margin for spikes. Auto = calculated by InfeRecipe based on model size and GPU VRAM.
max-num-seqsMax requests the engine processes simultaneously. Too high may cause out-of-memory; too low wastes GPU capacity. Auto = calculated by InfeRecipe from concurrent users and GPU count.
max-num-batched-tokensMax tokens processed in a single batch. Larger batches improve throughput but use more memory. Auto = calculated by InfeRecipe to match your workload.
dtypePrecision for model weights. Lower precision (float16) uses less GPU memory but may reduce quality slightly. Auto = vLLM detects from the model config.
kv-cache-dtypePrecision for KV cache (the engine's per-request working memory). FP8 halves cache memory, fitting more concurrent users. Auto = vLLM default (same as model dtype).
pipeline-parallel-sizeSplit model across GPU groups in sequence. Only needed when the model is too large for tensor parallelism alone. Auto = vLLM default (1).
block-sizeNumber of tokens per KV cache block. Larger blocks reduce management overhead for long sequences and improve NIXL KV transfer efficiency in P/D mode. Auto = next-power-of-2 of √(ISL+OSL). For P/D goals, minimum is 128 (NIXL transfers KV cache in blocks).
tool-call-parserHow the engine parses function/tool calls in the model output. Only needed if your app uses tool calling. Auto = vLLM default (disabled).
Toggle Flags
FlagDescriptionState
enable-prefix-cachingReuse computation for repeated prompt openings (e.g., system prompts). Saves GPU time when many requests share the same starting text. Auto = enabled by InfeRecipe.
disable-custom-all-reduceTurn off optimized GPU-to-GPU communication. Only enable if you see NCCL errors during multi-GPU runs. Auto = vLLM default (off).
enable-auto-tool-choiceLet the engine decide when to invoke tools/functions automatically. Only relevant if your application uses tool calling. Auto = vLLM default (off).
trust-remote-codeAllow the model to run custom Python code from HuggingFace. Required by some models (e.g., custom architectures), but has security implications. Auto = enabled by InfeRecipe.
disable-log-requestsStop logging individual request/response details. Reduces log volume and improves performance during benchmarks. Auto = enabled by InfeRecipe.
