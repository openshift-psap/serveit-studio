Controls how many of the best Prefill TP and Decode TP values (from Steps 2-3) are crossed to form TP pairs. Each pair then gets its own set of P/D ratio tests.

1 → Only the single best prefill TP × best decode TP. Fastest — 1 TP pair.
2 → Top-2 × Top-2 = up to 4 TP pairs. Good balance.
3 → Top-3 × Top-3 = up to 9 TP pairs. More coverage.
4 → All 4 × All 4 = up to 16 TP pairs. Most thorough.
Allow Asymmetric TP
Test configurations where prefill and decode use different TP sizes (e.g., Prefill TP1 / Decode TP4). Note: Some asymmetric TP combinations may fail on EP configs due to NIXL KV cache block count mismatches between different TP sizes. Failed configs are automatically retried and skipped.
Prefill / Decode Pod Balance
For each TP pair above, how many prefill-vs-decode pod ratios to test.
▸
For each TP pair, there are many ways to split GPUs between prefill and decode pods (e.g. 2 prefill + 6 decode, or 3 prefill + 4 decode). This controls how many of those ratios are actually deployed and tested.

Smart — Uses the throughput measured in Steps 2-3 to calculate where the prefill/decode pipeline is balanced, then tests only ~3 ratios around that optimum. Much faster, same accuracy in practice.
Exhaustive — Tests every valid pod ratio for each TP pair. Guarantees no split is missed, but can run 50+ tests on large clusters.

📊 Calibrated Load Testing
After finding the best configs, sweep concurrency and cache hit levels to map the full performance curve
▸
Calibrated Load Validation
Computes a per-config calibrated concurrency from each config's measured throughput and decode speed (ITL). Configs with headroom at the test concurrency get a higher calibrated value; overloaded configs get a lower one. Re-tests at this calibrated load to measure realistic production performance.
Concurrency Sweep
Runs selected configs at multiple concurrency levels centered on each config's calibrated value. Maps the full throughput/latency curve so you can see how each architecture degrades under load and find the optimal operating point.

⚙️ Auto-Tune vLLM Settings
Automatically optimizes memory, batch size, and engine settings. Override specific values below.
Enter vLLM serve arguments directly. One flag per line. Lines starting with # are ignored. The model name, --port, --tensor-parallel-size, --gpu-memory-utilization, and resource settings are managed by the optimizer and should not be included here.
Extra Environment Variables
Added to the vLLM pod container. One per line: NAME=value. Lines starting with # are ignored. To override a built-in variable, set it here — the last value wins.
Value Settings
SettingDescriptionModeValue
max-model-lenMax total text length (input + output) per request. Larger values reserve more GPU memory, leaving less for KV cache (fewer concurrent users). Auto = calculated by ServeIt Studio from your ISL + OSL.
gpu-memory-utilizationFraction of GPU memory the engine can use (0.0-0.99). Higher = more KV cache space for concurrent requests, but less safety margin for spikes. Auto = calculated by ServeIt Studio based on model size and GPU VRAM.
max-num-seqsMax requests the engine processes simultaneously. Too high may cause out-of-memory; too low wastes GPU capacity. Auto = calculated by ServeIt Studio from concurrent users and GPU count.
max-num-batched-tokensMax tokens processed in a single batch. Larger batches improve throughput but use more memory. Auto = calculated by ServeIt Studio to match your workload.
dtypePrecision for model weights. Lower precision (float16) uses less GPU memory but may reduce quality slightly. Auto = vLLM detects from the model config.
kv-cache-dtypePrecision for KV cache (the engine's per-request working memory). FP8 halves cache memory, fitting more concurrent users. Auto = vLLM default (same as model dtype).
pipeline-parallel-sizeSplit model across GPU groups in sequence. Only needed when the model is too large for tensor parallelism alone. Auto = vLLM default (1).
block-sizeNumber of tokens per KV cache block. Larger blocks reduce management overhead for long sequences and improve NIXL KV transfer efficiency in P/D mode. Auto = next-power-of-2 of √(ISL+OSL). For P/D goals, minimum is 128 (NIXL transfers KV cache in blocks).
tool-call-parserHow the engine parses function/tool calls in the model output. Only needed if your app uses tool calling. Auto = vLLM default (disabled).
reasoning-parserParser for chain-of-thought / reasoning extraction. Required for reasoning-capable models (e.g., DeepSeek-R1, Qwen3). Auto = disabled.
chat-template-content-formatHow chat message content is formatted before passing to the template. Some models (GLM) require 'string' instead of the default. Auto = vLLM default.
dbo-prefill-token-thresholdMinimum tokens to trigger Dual Batch Overlap on prefill. Lower = more aggressive overlap. Only applies when DBO is enabled (MoE/EP). Auto = 32 (upstream default).
dbo-decode-token-thresholdMinimum tokens to trigger Dual Batch Overlap on decode. Lower = more aggressive overlap. Only applies when DBO is enabled (MoE/EP). Auto = 32 (upstream default).
moe-backendComputation backend for MoE expert layers. DeepGEMM provides optimized kernels for DeepSeek-style models. Only applies to MoE models. Auto = deep_gemm when MoE detected.
all2all-backendCommunication backend for MoE expert-parallel all-to-all exchanges. High-throughput for prefill, low-latency for decode. Only applies to MoE/EP models. Auto = deepep_high_throughput (prefill) / deepep_low_latency (decode).
headroomSafety margin for sustainable throughput calculation. The cluster's theoretical max throughput is divided by this value to avoid benchmarking at saturation. Higher = more conservative. Auto = 1.3 (30% headroom).
memory-reserve-pctAdditional GPU memory to reserve as safety margin when calculating minimum TP. Prevents OOM from activation spikes, CUDA fragmentation, or unexpected overhead. Applied on top of model weights + KV cache estimate. Auto = 0% (no extra reserve). %
model-loader-extra-configJSON config for model loading optimization. E.g. {"enable_multithread_load": true, "num_threads": 96} for faster loading of large models (550B+). Auto = vLLM default.
cpu-offload-gbCPU memory (GB) for KV cache offloading via OffloadingConnector. Extends prefix cache beyond GPU HBM for long agentic sessions. Only applies to PD disaggregated mode. Auto = disabled. GB
weight-cpu-offload-gbOffload model weights from GPU to CPU RAM (vLLM --cpu-offload-gb). Frees GPU memory for KV cache at the cost of slower inference. Use when the model barely fits in GPU memory and needs more room for KV cache. Auto = disabled (all weights on GPU). GB
disk-offload-kvOffload KV cache to local NVMe disk. Stores cached prefixes as files on the node's local disk, extending prefix cache beyond GPU+CPU memory and persisting across pod restarts. All pods on the same node share the cache. Only works when local disk storage is selected — uses the same hostPath NVMe mount. Auto = disabled. R W threads
http-timeout-keep-aliveHTTP keep-alive timeout in seconds. Increase for long-running agentic requests that may idle between tool calls. Auto = vLLM default (5s). sec
prefix-cache-retentionPrefix cache retention interval (VLLM_PREFIX_CACHE_RETENTION_INTERVAL). Set to 0 for Mamba-hybrid models to improve multi-turn prefix cache hit rates. Auto = vLLM default. Set 0 for Nemotron.
ssm-conv-state-layoutSSM convolution state layout (VLLM_SSM_CONV_STATE_LAYOUT). Required for Mamba-hybrid models like Nemotron. Auto = vLLM default. Set DS for Nemotron.
num-speculative-tokensNumber of tokens predicted per step using Multi-Token Prediction (MTP). Requires a speculative model to be set below. Auto = disabled (no speculative decoding).
speculative-modelHuggingFace model for MTP speculative decoding. E.g. google/gemma-4-26B-A4B-it-assistant for Gemma 4. If empty, uses the main model. Auto = use main model.
Toggle Flags
FlagDescriptionState
enable-prefix-cachingReuse computation for repeated prompt openings (e.g., system prompts). Saves GPU time when many requests share the same starting text. Auto = enabled by ServeIt Studio.
disable-custom-all-reduceTurn off optimized GPU-to-GPU communication. Only enable if you see NCCL errors during multi-GPU runs. Auto = vLLM default (off).
enable-auto-tool-choiceLet the engine decide when to invoke tools/functions automatically. Only relevant if your application uses tool calling. Auto = vLLM default (off).
enable-expert-parallelSplit MoE experts across GPUs instead of replicating them. Saves memory and improves throughput for Mixture-of-Experts models (Mixtral, DeepSeek-MoE). Auto = enabled when MoE model detected.
enable-dboDual Batch Overlap — overlaps MoE all-to-all communication with compute for higher throughput. Only for Expert Parallel models. Auto = enabled when MoE model detected.
enable-eplbExpert-Parallel Load Balancing — replicates heavily-used MoE experts to reduce imbalance across GPUs. Uses ~2GB extra per redundant expert per GPU. Auto = enabled when MoE model detected.
trust-remote-codeAllow the model to run custom Python code from HuggingFace. Required by some models (e.g., custom architectures), but has security implications. Auto = enabled by ServeIt Studio.
disable-log-requestsStop logging individual request/response details. Reduces log volume and improves performance during benchmarks. Auto = enabled by ServeIt Studio.
vllm-debug-logsEnable verbose vLLM engine logs. Useful for debugging model loading, KV cache, and scheduling issues. Generates a lot of output. Auto = off (ERROR level only).
nccl-debug-logsEnable verbose NCCL communication logs. Useful for debugging multi-GPU networking, RDMA, and InfiniBand issues. Very noisy. Auto = off (ERROR level only).
enable-bidirectional-kvEnable bidirectional KV transfer in NixlConnector. Allows both prefill and decode to send/receive KV cache. Required for Nemotron-3 and agentic serving. Auto = off.
