EPP Configuration

Configure how the gateway routes inference requests to your pods. The Endpoint Picker (EPP) uses scoring plugins to decide which pod handles each request.

Scoring Strategy
Choose how the gateway picks which pod gets each request. Each strategy uses different weights for cache hits, queue depth, and memory utilization.

Scoring Plugins
PluginEnableWeight
prefix-cache-scorer
Routes to pods that already have parts of the prompt cached in GPU memory.
kv-cache-utilization-scorer
Favors pods with more free GPU memory for KV cache (can handle longer sequences).
queue-scorer
Favors pods with shorter request queues. Prevents overloading a single pod.
slo-scorer
Uses predicted latency to route requests to pods that can meet the SLO target. Requires latency SLA to be enabled.

How many KV cache blocks the gateway checks when looking for prefix cache hits on each pod. Higher values find more cache matches but take longer to score. Should cover your longest prompt — ceil(ISL / block_size). With prefix cache enabled, this is multiplied to catch longer shared prefixes.
How many cache block entries the gateway tracks per vLLM pod. The gateway maintains a local index of which prompts each pod has cached. Larger values let the gateway remember more cached prefixes for smarter routing. Estimated from GPU VRAM: (VRAM × 40%) / (block_size × 0.5KB).
When a request arrives, the gateway checks how many prompt tokens are not already cached on a decode pod. If the uncached portion exceeds this threshold, the request is routed to a prefill pod first. If it's below, the decode pod handles it directly (saving the round-trip). Lower values = more aggressive prefill routing. Default: 16 tokens.
Benchmark EPP Strategies
After finding the best deployment, test 2-3 different scoring strategies on the same pods to find the optimal routing. Adds ~15 min per strategy.
When enabled, the optimizer will take the best-performing deployment config and re-run the benchmark with different EPP scoring strategies — keeping the same pods but changing only how requests are routed. This isolates the impact of EPP scoring on performance.
