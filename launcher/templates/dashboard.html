Getting Started

ServeIt Studio is a multi-cluster LLM inference optimization platform. Use this dashboard to manage clusters, create instances, and run optimizations.

Clusters

Local cluster uses your current Kubernetes context. Remote clusters require a kubeconfig file — upload it when creating the cluster and the system will validate connectivity and store it securely as a K8s Secret.

Click Rescan to refresh GPU, CPU, memory, and RDMA information from the cluster.

Instances

Each instance is an isolated ServeIt Studio deployment with its own database and optimization runs. Click + New Instance to create one.

  • GPU Allocation — Limit how many GPUs an instance can use. Leave empty for full cluster access.
  • Node Pinning — Restrict tests to specific machines. Useful for shared clusters or specific hardware.
Connecting to an Instance

OpenShift — Instances get a Route URL automatically. Click Open to access directly.

Vanilla Kubernetes — No built-in ingress. Use the "📋 Copy portforward cli" button to copy a kubectl port-forward command. Paste it in your terminal to create a local tunnel, then click Open.

GPU Node Visualization

The Cluster Resources panel shows detected hardware. Each node card displays:

  • Green LEDs — Node is Ready
  • Red LEDs — Node is Not Ready
  • Teal bars — Individual GPU slots
  • RDMA — Node has InfiniBand/RoCE for fast GPU-to-GPU networking
Deleting Instances

When deleting, you'll be asked whether to backup the optimization database. If enabled, the results are copied to the launcher's storage at /mnt/storage/backups/ before the instance is removed.
